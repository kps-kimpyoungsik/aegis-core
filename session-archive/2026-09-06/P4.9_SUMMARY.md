# P4.9 — Artifact/Object Storage Physical Integration Harness

Status: **P4_9_HARNESS_READY_PHYSICAL_BLOCKED**

P4.9 adds only the physical object-storage integration verification responsibility. It reuses BlobStorePort, BackupRestorePort, the canonical dataset ownership model, the Object Storage physical profile, and the P4.8 integrity/lineage rules. It does not implement a second production object adapter or acquire semantic ownership of `asset.registry.canonical`.

The required physical gate covers provider bootstrap, stage→hash/size verify→publish, digest mismatch rejection, idempotent same-digest put, immutable digest protection, partial upload isolation, restart persistence, verified readback, verified restore, and destructive-delete authority/retention control. Advanced multipart/object-lock/replication cases remain optional until a capable provider topology is available.

The harness first attempts local MinIO, then Docker/Podman MinIO. This execution environment has none of `minio`, `mc`, `docker`, or `podman`, therefore the physical attempt correctly exited 20 with an explicit environment block. No physical integration promotion was made.
